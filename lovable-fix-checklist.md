# Lovable-built site fix checklist

Things heard in the wild about Lovable-built websites that are missing, must be fixed, or must be said. Each item carries its source. Mark items done yourself with `[x]` — the watch never marks them.
Last run: 2026-10-03 07:47 EDT — rotation 7 (Lovable-built website issues: SEO invisibility, accessibility failures, security-header gaps, perf auditing). Brand check: no third-party liqlearns.com mentions (only the user's own GitHub repos surfaced).

## Must-fix / commonly missing
- [ ] Per-page meta titles, meta descriptions, and Open Graph / social-preview tags are missing on deployed routes — shared links render with no preview. Source: https://prerender.io/blog/how-to-make-lovable-websites-seo-friendly/
- [ ] Crawlers may see only an empty `<div id="root"></div>` shell — the site can be invisible to Google and AI search until content is properly rendered. Verify in Google Search Console → URL Inspection → "View tested page", not via free SEO scanners (they get the unverified shell). Sources: https://prerender.io/blog/how-to-make-lovable-websites-seo-friendly/ and http://dev.to/geminate_solutions_9b6035/lovable-seo-why-your-live-app-is-not-showing-on-google-30mh
- [ ] No JSON-LD structured data, canonical URLs, or route-specific metadata management — metadata doesn't auto-update across routes. Source: https://prerender.io/blog/troubleshooting-lovable-cloudflare-integration/
- [ ] Wasted crawl budget: heavy JS bundles downloaded per URL, same empty shell on every route, harming crawlability/indexability site-wide. Source: https://prerender.io/blog/troubleshooting-lovable-cloudflare-integration/
- [ ] Older Lovable projects (pre ~April/May 2026 SSR rollout) don't get native server-side rendering — only on-request pre-rendering for verified crawlers (Google, Bing). Check which stack liqlearns.com is on. Source: http://dev.to/geminate_solutions_9b6035/lovable-seo-why-your-live-app-is-not-showing-on-google-30mh
- [ ] AI discovery engines (ChatGPT, Perplexity, Claude, Gemini) and social-preview bots often don't run JavaScript — no rendered HTML means no visibility there (AEO gap, not just SEO). Source: https://prerender.io/blog/how-to-make-lovable-websites-seo-friendly/
- [ ] The generic AI look erodes trust: "the moment a visitor's brain registers 'this looks AI-made,' trust quietly drops — before they've read a single word of your actual offer." Break framework defaults — custom type pairing, real color decisions, non-default spacing. (LiqLearns has exact repo tokens #172A4F navy / #FFA53D orange / Lexend — confirm the live site actually uses them.) Source: https://medium.com/@dimassskq/your-vibe-coded-site-is-trash-ce22c42b6c05
- [ ] Landing-page CRO gaps AI never asks about: no social proof above the fold, headline describes the product instead of the visitor's problem, CTA says "Get Started" and tells the visitor nothing. Audit the liqlearns.com hero against these. Source: https://medium.com/@apeoid/you-vibe-coded-a-landing-page-now-nobody-converts-b6e423e61748
- [ ] AI co-authored code ships ~1.7x more major issues than human-written code (CodeRabbit, Dec 2025) — keep human review on every Lovable output before it reaches kids' data or billing. Source: https://medium.com/@apeoid/you-vibe-coded-a-landing-page-now-nobody-converts-b6e423e61748
- [ ] AI-generated code introduced security vulnerabilities in 45% of cases (Veracode 2025); XSS/log-injection failures at 86%/88% — run a security pass over auth, billing, and payment code on every ship. (Supports the server-side-only credential rule already adopted.) Source: https://www.ishir.com/blog/344522/how-do-you-clean-up-a-vibe-coded-application-before-it-goes-into-production.htm
- [ ] If organic search matters, plan the stack early: hybrid approach (server-rendered marketing site + Lovable app layer) beats bolting SEO onto a client-rendered SPA later. Source: https://mcstarters.com/blog/lovable-seo-problems/

- [ ] One-click cancel for auto-renewing subscriptions + a charge reminder before each renewal — silent auto-renew with near-impossible refunds is the #1 billing complaint pattern (MasterClass ~1.6–1.7★ on Trustpilot's own pages: "nearly impossible to get a refund"; the Lumosity FTC order forced one-click cancel on the company). Source: https://ca.trustpilot.com/review/masterclass.com?page=9 and https://www.ftc.gov/business-guidance/blog/2016/01/mind-gap-what-lumosity-promised-vs-what-it-could-prove
- [ ] Verify purchase restore actually unlocks paid content on every platform/build — "Everything else in the app is invisible to someone who sees a lock on what they paid for." (indie brain-training app shipped a broken iOS restore and ate one-star reviews). Source: https://dev.to/strobolt/three-months-after-shipping-a-brain-training-app-on-ios-alone-the-restore-bug-the-paywall-5f1m
- [ ] Publish the free-vs-paid line on the pricing page; never move a free feature behind the paywall after launch — reviews collapsed to "was free, now paid" within two days. Source: https://dev.to/strobolt/three-months-after-shipping-a-brain-training-app-on-ios-alone-the-restore-bug-the-paywall-5f1m
- [ ] No efficacy claims without evidence on marketing pages — no "improves memory / prevents decline" language anywhere; Lumosity paid $2M to the FTC for exactly this. Source: https://www.ftc.gov/business-guidance/blog/2016/01/mind-gap-what-lumosity-promised-vs-what-it-could-prove
- [ ] Senior-friendly stability: no forced-flow churn, no tiny-text/password mazes; copy must treat older adults as competent adults, never condescend — "the barrier is almost never intellectual... it's that nobody ever took the time to explain it clearly, without condescension." Source: https://medium.com/@tech4grownups/the-elderly-tech-industry-is-condescending-by-design-heres-what-older-adults-actually-need-12a29e7467b8

## New this run (2026-10-03 07:47 EDT — rotation 7, Lovable-built website issues)
- [ ] Verify security headers on the live deploy — an external scan of 190 live Lovable apps found 94% send no Content-Security-Policy header and 91% send no X-Frame-Options (so any other site can frame the page). "Boring config the builder never shows you." Source: https://www.indiehackers.com/post/i-scanned-190-live-lovable-apps-from-the-outside-189-had-at-least-one-issue-20b8be97ae
- [ ] Bogus URLs must return a real 404 status — 79% of scanned Lovable apps answered a made-up URL with a normal 200 page. Source: https://www.indiehackers.com/post/i-scanned-190-live-lovable-apps-from-the-outside-189-had-at-least-one-issue-20b8be97ae
- [ ] Set a real DMARC policy on the domain (not p=none) — 67% of scanned apps had none, so anyone can send mail that looks like it came from the domain. Source: https://www.indiehackers.com/post/i-scanned-190-live-lovable-apps-from-the-outside-189-had-at-least-one-issue-20b8be97ae
- [ ] Scan the shipped client bundle for leaked API keys — the scan found live Lovable apps shipping Google/Firebase API keys in the bundle (fine if restricted, a surprise bill if not). Source: https://www.indiehackers.com/post/i-scanned-190-live-lovable-apps-from-the-outside-189-had-at-least-one-issue-20b8be97ae
- [ ] Lovable has no built-in performance auditing — nothing tells you if the app is slow. Run Google PageSpeed Insights / Lighthouse after EVERY major feature or design change (regressions arrive silently); when prompting a fix, quote the tool's specific finding ("my images aren't optimized") instead of "make it faster". Sources: https://mcstarters.com/blog/lovable-has-no-built-in-performance-auditing/
- [ ] Images must be compressed and served as WebP/AVIF (unoptimized JPEGs/PNGs are the #1 slowdown); audit and remove non-critical third-party scripts; keep mobile Largest Contentful Paint under 2.5s. Source: https://aifunn.com/blog/lovable-website-builder-checklist-conversion-killers
- [ ] Accessibility prompt-for-and-verify: AI builders including Lovable failed WCAG Level A on all 15 test sites in Oct 2026 testing — even when explicitly asked to comply (avg 55 issues/page, 91% medium/high severity). Prompt with specifics ("alt text and aria-labels, semantic elements, ensure 4.5:1 contrast"), then still audit keyboard navigation, focus order, and keyboard traps by hand — generic "make it accessible" does not fix flow-level issues. Sources: https://venturebeat.com/technology/we-asked-five-ai-tools-to-build-accessible-websites-all-15-sites-failed and https://vibedoctor.io/blog/european-accessibility-act-enforcement-ai-generated-ui
- [ ] Audit for duplicate meta titles across routes ("everything is Blog" titles), missing/weak alt text, and non-descriptive image filenames — Google reads visuals through them. A live Lovable audit's fix prompt: semantic HTML + JSON-LD + proper meta tags + noscript fallback content. Source: https://www.youtube.com/watch?v=3AeU2vtNLiU
